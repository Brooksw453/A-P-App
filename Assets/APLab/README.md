# A&P Lab — App Framework (`Assets/APLab`)

Content-driven framework for the Anatomy & Physiology mixed-reality companion
(Meta Quest 3). The design goal: **adding a simulation = authoring a
`ModuleDefinition` asset + dropping in a model**, not hand-building a scene.

## Backend
Supabase project **Course Dashboard** (`awcmkderlpyxpkmrnvwi`). The VR app shares
the existing online-course auth + dashboards. VR-specific tables were added
without touching any existing table:

| Table | Purpose |
|-------|---------|
| `vr_modules` | Catalog of simulations (slug, unit, course/chapter/section mapping) |
| `vr_sessions` | Per-module time tracking (duration_seconds) |
| `vr_lab_attempts` | Scores per attempt (mirrors `quiz_attempts`) |
| `vr_pairing_codes` | Device-code login (service-role / edge-function only) |

Edge functions: `vr-pair-start`, `vr-pair-approve`, `vr-pair-poll` (device-code
login), and `vr-sync-result` (writes a lab attempt, upserts `section_progress`,
logs `activity_log` so results appear in the existing instructor dashboards).

> `vr-sync-result` writes into existing production tables and is deployed
> separately with explicit authorization.

## Sign-in (device-code pairing — no typing in VR)
1. Quest calls `vr-pair-start` → shows a short code (e.g. `9QMAKY`) and the
   `/link` URL.
2. Student opens `/link` on a phone/laptop (already logged into the course),
   enters the code → web calls `vr-pair-approve` with their JWT.
3. Quest polls `vr-pair-poll`; on approval it receives a magic-link
   `token_hash`, calls GoTrue `/verify`, and gets a real session.
`SupabaseClient.DeviceLoginFlow()` implements this end to end.

## Runtime pieces
- `Config/APLabConfig` — Supabase URL, publishable key, function names, `/link` URL.
- `Core/APLabManager` — bootstrap singleton; restores session, flushes offline queue.
- `Backend/SupabaseClient` — auth, token refresh/persist, PostgREST, edge functions.
- `Backend/Dtos` — serializable payloads/rows.
- `Core/SessionTracker` — opens/closes `vr_sessions`.
- `Core/ModuleDefinition` (+ `LabelSet`, `LearnSequence`, `PracticalTask`) — content schema.
- `Core/ModuleRunner` — Learn → Practice → Assess → Results state machine.
- `Core/ScoreModel` — practical rubric + quiz → normalized mastery (0..1).
- `Core/LocalCache` — offline result queue (PlayerPrefs), retried on next sign-in.

Reuses the existing `QuizData`/`QuizManager` (in `Assets/Scripts`) for the Assess phase.
